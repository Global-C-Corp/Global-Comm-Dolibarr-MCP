# Global Comm Dolibarr MCP — gap analysis (Phase 0)

**Date / source:** 2026-09-25; upstream [`digitalfactorysn/mcp-dolibarr`](https://github.com/digitalfactorysn/mcp-dolibarr/tree/360cb7c66e470a1c844f22320573c2ced2f01c4d) at commit `360cb7c66e470a1c844f22320573c2ced2f01c4d` (`master`). This is a source and mock-only audit; Global Comm production ERP was neither queried nor modified. `UPSTREAM_TOOL_INVENTORY.md` enumerates all 186 declarations.

## Baseline and verification limits

- **Build:** `npm ci --ignore-scripts --no-audit --no-fund` fails before installation: `package.json` and `package-lock.json` disagree (package 2.1.0 vs lock root 2.0.0; Express 4 vs Express 5; missing Express typings and transitive records). After `npm install --no-save --package-lock=false --ignore-scripts --no-audit --no-fund`, `npm run build` passes with Node 24.19.0/npm 11.9.0. This proves type compilation under a newly resolved dependency tree, **not** reproducible installation or runtime API correctness.
- **Tests and lint:** no test files, test script or lint script were found. Existing workflow is deployment only (`.github/workflows/*`). A mock in-memory MCP client received 186 `tools/list` entries, 183 unique names. With `DolibarrAPI.prototype.post` intercepted locally, calling `set_setup_value` reached `POST /setup/conf` and returned success without human approval or a network call.
- **Upstream activity:** open issues [#2](https://github.com/digitalfactorysn/mcp-dolibarr/issues/2), [#3](https://github.com/digitalfactorysn/mcp-dolibarr/issues/3) and [#5](https://github.com/digitalfactorysn/mcp-dolibarr/issues/5) report API mismatches; open PRs [#6](https://github.com/digitalfactorysn/mcp-dolibarr/pull/6) and [#7](https://github.com/digitalfactorysn/mcp-dolibarr/pull/7) propose fixes. Those reports concern Dolibarr 23.x and have **not** been validated against Global Comm's Dolibarr 24.x.
- **Dolibarr 24.x:** endpoint, payload, module and permission details remain **UNVERIFIED** for the target installation. The official [Dolibarr REST guide](https://wiki.dolibarr.org/index.php/Module_Web_Services_REST) says the instance's API explorer is authoritative and that interacting with its explorer can modify data. Do not execute writes there in Phase 0.

## Current state vs Global Comm target

Each row gives **current state; evidence; risk; target state; action**. Severity reflects *potential impact if deployed with production credentials*, not a claim that exploitation occurred.

## Reuse before rewrite

| Component | Decision | Reason |
|---|---|---|
| `src/api.ts` Axios wrapper | KEEP + HARDEN | Shared REST client, timeout and key injection are reusable; add URL allowlist, redirect/response limits, normalized errors and redaction. |
| `src/index.ts` stdio transport | KEEP + HARDEN | Small, isolated transport; revalidate against Claude after registry/auth changes. |
| `src/http.ts` remote transport | REFACTOR | Working structural starting point; authorization, origins, sessions and version support need rework. |
| Core third-party/project/proposal/order/invoice handlers | KEEP + HARDEN / REFACTOR per tool | Reuse verified request mapping; remove unsafe pass-through and hardcoded IDs. |
| Accounting/HR/static configuration guides | REMOVE or DISABLE BY DEFAULT | Environment-specific output and broad scope do not match Global Comm target. |
| Existing deploy scripts/workflow | REPLACE | Assumed Digital Factory host, privileged deployment and mismatched ports. |

## Blockers before any production connection

1. No verified Dolibarr 24.x API matrix, module list or rights for `gc_ai`.
2. No staging or controlled fixture to test any write operation.
3. No secure remote MCP authentication design and client compatibility verification.
4. No passing reproducible installation or automated tests.
5. Global Comm's target repository creation/access has not been established; Phase 1 has **not** begun.

**Phase 0 decision:** upstream is a useful prototype, but it does not meet the specified production gates. See `ARCHITECTURE.md`, `SECURITY.md`, `UPSTREAM_TOOL_INVENTORY.md`, and `MCP_UPGRADE_PLAN.md` for the proposed implementation path.
