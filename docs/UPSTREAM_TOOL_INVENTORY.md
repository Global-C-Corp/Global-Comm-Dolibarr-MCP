## Important implementation-specific qualifications

- `accounting_config.ts` uses `if` dispatch; its endpoint calls were traced manually. Its `configure_*` methods are static guides, **not** API mutations. `configure_bank_accounting` only reads and returns an upstream-vendor URL.
- `get_trial_balance` and `export_accounting_entries` try `/accountancy/bookkeeping` then read invoices in a fallback helper (`accounting_advanced.ts:15-38`); the fallback does not represent a verified general ledger.
- `list_leave_types`, `initialize_syscohada`, and `list_online_payments` return static or environment-specific content without querying the relevant ERP state.
- `generate_document_pdf` calls `GET /documents/builddoc`; method alone would misclassify its possible server side effect.
- The advertised description is copied from upstream; for some tools the actual method, accounting semantics or data source differs. Proposed status follows the **handler**, not its name.
- API permissions, required modules, payloads and actual behavior must be mapped against the **specific** Dolibarr 24.x instance before any tool is enabled.

**Counts by proposed status:** ALLOW=23, ALLOW_WITH_AUDIT=21, CONFIRM=24, DISABLE=17, NEEDS_REVIEW=89, REMOVE=12. Counts cover declarations, including the three shadowed duplicates.
